## CADRAGE

Goal:
Étendre la palette de couleurs disponibles dans l'app Atelier pour permettre à Arnaud de mieux différencier visuellement ses projets / epics / (sprints ?). Aujourd'hui la palette est limitée à 6 couleurs partagées entre clients (sidebar) et epics (chip + sélecteur), et **les sprints n'ont aucune couleur** distinctive. Le ticket Atelier ATE-26 dit : "Disposer de quelques couleurs supplémentaires pour les projets, les epics et les sprints".

Persona impact:
- **Arnaud / utilisateur Atelier** — gain de différenciation visuelle quand il jongle entre plusieurs clients/epics. Surtout utile si > 6 projets ou epics actifs (sinon la palette actuelle suffit).
- **Claude Code / Codex** — chantier petit (CSS palette + extension UI), surface limitée, faible risque de régression.
- **Utilisateur final** — aucun changement métier ; seul l'affichage visuel des chips/dots/badges change.

Context:
- **Palette actuelle** (`index.html` ligne 5171) : `EPIC_COLORS = ['#0052cc', '#36b37e', '#8777d9', '#ff8b00', '#e5493a', '#4bade8']` (6 couleurs : bleu primaire, vert, violet, orange, rouge, bleu clair).
- **Réplique inline** ligne 3560 dans `renderSidebar()` : même tableau hardcodé pour assigner une couleur de fallback aux clients qui n'ont pas de `c.color` explicite.
- **Modals UI** :
  - `epicColors` (ligne 2109) — sélecteur swatches dans la modale Epic (CRUD epic).
  - `clientColors` (ligne 2138) — sélecteur swatches dans la modale Client (CRUD client).
  - Les deux utilisent la même palette `EPIC_COLORS`.
- **Sprints** : `_normalizeSprint` (ligne ~2548) gère `id, name, startDate, endDate, active, completed` — **pas de champ `color`**. Les sprints sont rendus dans la sidebar avec un dot statique (`var(--story)` actif / `var(--text-mute)` future / `var(--text-faint)` terminé). Pas de personnalisation visuelle aujourd'hui.
- **`DEFAULT_EPIC_COLOR`** (ligne 2520) = `'#0052cc'` (premier du tableau, fallback validation import).

Constraints:
- **Cohérence dark theme** : nouvelles couleurs doivent rester lisibles en mode sombre (contraste suffisant sur `--bg-app` / `--bg-col`).
- **Rétro-compatibilité Gist** : items / clients / epics existants gardent leur couleur. Si on ajoute `sprint.color`, le champ est optionnel (fallback ancien comportement = pas de couleur).
- **Centralisation** : la palette doit être **une seule source de vérité** (dédupliquer ligne 5171 vs ligne 3560).
- **Pas de refonte design system** : on étend la palette, on ne change pas les tokens CSS (`--primary`, `--bg-app`, etc.).

Out of scope:
- Couleurs personnalisées (color picker libre) — palette restreinte conservée.
- Drag & drop pour réorganiser les swatches.
- Thèmes utilisateur (dark/light forçés, palettes alternatives).
- Refonte du sélecteur de couleurs en UI plus riche (gradient, opacity, etc.).
- Couleur sur les **items individuels** (déjà différenciables par type/priority/status, hors-scope).
